# CIMD Lab

Standalone Demo (tier) that teaches CIMD both ways, plus the H2 2026 tab: a local simulation of an MCP gateway that prefers CIMD (Ping release claim, UNVERIFIED on our tenant). Read `README.md` for what is simulated. Rules: `~/Development/STANDALONE-RULES.md`.

- Run: `npm install && npm start` (port 5250, loopback only; `docker compose up --build -d` publishes 127.0.0.1 only). Test: `npm test` (`node --test test/*.test.js` and vitest, Node 26 only, engines >=26).
- Direction 1 talks to REAL PingFederate only (owner decision 2026-10-28). `PF_BASE_URL` has NO default (an agent once hit a shared local PingFederate through the old default): unset means 409 `pf_not_configured` and no request. Tests set `https://pf.invalid:9031` with a stub fetch; never set it to a real host in a test or an agent run. Never probe the shared `ai-demo-pingfederate` container from an agent; the owner runs those checks.
- Direction 2 is the lab's own server (`server/src/authserver.js`) plus the tester (`server/src/tester.js`); fixtures in `fixtures.js`.
- Rules that bite: no identifiers from other projects (only `.example`/`.invalid` hosts in code and tests); no EC `generateKeyPair`; client secrets never returned or logged; only loopback and the one configured PF origin may be contacted (tests assert it).
- Port range 5250-5299 (board claim 2026-10-29). No GitHub repo, SE deploy or PF config write without owner approval.
- Hosted build: `MODE=hosted` + `PUBLIC_HOST` (SE k8s, not "mock-only": direction 1 is real PF, owner exception to rules 1 and 18). Rate limit and X-Forwarded-For only in hosted mode. `k8s/` uses `__IMAGE__`, `__SE_HOST__`, `__PF_BASE_URL__`; `scripts/deploy-se.sh` needs `NAMESPACE`, supports `DRY_RUN=1`; agents never apply it.
- PingFederate acting as a CIMD client is **measured NOT SUPPORTED (2026-11-05, PF 13.1 local)**: the only PF-as-OAuth-client feature is the OIDC IdP connection, whose Authentication Scheme offers exactly BASIC / POST / PRIVATE KEY JWT / CLIENT SECRET JWT (read from the live console, no `none`), OIDC discovery is mandatory, and Client ID / Client Secret are required fields. The configuration surface has no setting to publish or fetch a client metadata document for the outbound client, so a remote AS has no way to treat PF as a CIMD client. A URL `client_id` string is accepted by the field but the remote AS never sees CIMD semantics. Do not claim PF can be a CIMD client; cite this measurement. Rollback of the PF objects is in README under "PingFederate setup".
- Workspaces (`server/src/workspace.js`): all authorization server state is keyed by `req.workspaceId`; hosted = signed `cimd_ws` cookie (never trust a client-supplied id); the tester passes a one-run `x-cimd-internal` token so its loopback calls land in the caller's workspace. Stories live in `stories/` with `{{cast.x}}` tokens (`server/src/stories.js`); after editing them run `node scripts/build-talk-track.mjs` (a test checks `docs/talk-track.md`). Branding/vocabulary: `customer.config.json` (`server/src/customer.js`; accent must meet contrast and not be purple).
- H2 2026 tab (slide 36 of the Ping deck): engine `server/src/gateway-sim.js` (pure, no network; claims in `gateway-sim-claims.js`; Mock table `gateway-sim-table.json` GENERATED by `npm run mock-table`, a drift test fails if it differs). Web: `web/src/views/H2View.jsx`, diagram `gateway-cimd-preference`. Every row/step has ONE tag (a step that mixes a deck sentence with lab text keeps the deck sentence in `detail` and puts each lab addition in `notes[]` with its own tag): deck claim / console swagger name (schema only) / lab reading / lab-invented / measured (our note). Never tag something a deck claim unless slide 36 says it (the failure policy, check order, allowlist matching and cache expiry are NOT in the deck). The banner "Ping release claim, UNVERIFIED on our tenant" stays on every tab and in presenter mode. This tab never touches PingFederate or `PF_BASE_URL`; do not change the PingFederate lane.
- Masking (`server/src/credentials.js`, `mask.js`): everything echoed from the H2 2026 route is cleaned (controls and Cf deleted, NFKC, every space-like character read as a space and a second look with tab/LF/CR/U+2028/U+2029 deleted, 3 percent-decode rounds then a value still encoded is masked whole as `[masked:undecodable]`, masked BEFORE truncating) and the whole response goes through `maskDeep`. A heuristic: say so. Unknown JSON keys are refused without naming them. Tests assert literal numbers (20 allowlist entries, 2048 characters, attempts 1 to 5, body 64 KB).
- Missing static files are a JSON 404, wrong methods on known routes (and POST to a page or a file of the web UI) a 405 with Allow (`ROUTE_METHODS` in `app.js`, matched case-insensitively with one trailing slash ignored, like Express): add new routes to that table. `OPTIONS` is 405 on app routes and Express's automatic 200 under `/as` (no CORS headers): kept, documented in the README.
- `GET /as/authorize` shows the typed `client_id` through the display mask (`show` in `authserver.js`); validation always runs on the raw value.
- Conformance is a MANUAL step (the CI job was removed, it always skipped on hosted runners): `node <demo-kit-base checkout>/scripts/conformance.mjs . --new --tier=Demo`. Hosted copy history and the by-content verification: `docs/hosted-history.md`. `npm start` uses `--env-file-if-exists`, so no `.env` is needed.
- Shared stylesheet `web/src/standalone-ui.css` is vendored byte for byte from AI-DEMO-Standalone: never edit it. App CSS: tokens only (`check-css.sh`). After touching the family files run `check-drift.sh` and `check-css.sh`.
